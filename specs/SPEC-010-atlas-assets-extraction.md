# SPEC-010: Атласы глифов в `assets/` + build step

| Поле | Значение |
|---|---|
| **Приоритет** | 🟡 Средний |
| **Категория** | Repository size / build infrastructure |
| **Файлы** | `src/core/atlas.ts` (887 KB), `src/core/atlas-gray.ts` (4 MB), `scripts/gen-atlas.ts` |
| **Связь с аудитом** | пункт 4.6 |
| **Объём работ** | 4-6 часов |
| **Breaking change** | Да: меняется способ загрузки атласа; npm-пакет API может быть затронут |

## Проблема

Атласы глифов (font atlas) хранятся прямо как TypeScript-исходники:

- `src/core/atlas.ts` — 887 KB (base64-encoded bitmap/atlas data с inline-строками).
- `src/core/atlas-gray.ts` — 4 MB (аналогично).

Всего **~5 MB исходников** в репо. Это:
1. **Раздувает git history** при каждом изменении атласа (что бывает при добавлении символов).
2. **Замедляет клонирование** для контрибьюторов.
3. Делает PR diffs с изменениями атласа нечитаемыми.

Атлас пересоздаётся через `scripts/gen-atlas.ts` (запускается как `pnpm run build:atlas`), но **артефакт** остаётся в исходниках.

## Требования

1. Вынести бинарные атласы из `src/` в `assets/`.
2. `assets/atlas.json` и `assets/atlas-gray.json` — JSON с необходимыми массивами/структурами.
3. Добавить `assets/*.json` в `.gitignore` (но `assets/.gitkeep` — под git).
4. Обновить `scripts/gen-atlas.ts` — пишет в `assets/`, не в `src/core/`.
5. Обновить `src/core/library.ts` (или узкое место, где атлас грузится) — читает JSON с диска при первом импорте.
6. Добавить `pnpm run prepare-atlas` в `prepublishOnly` и опционально в `postinstall`.

`src/core/atlas.ts` после спеки:
```ts
/**
 * Glyph atlas loader. Atlas data is generated by `pnpm run build:atlas`
 * which writes JSON to assets/. The data is loaded lazily on first use
 * to avoid parsing 5 MB at module-import time.
 *
 * Atlas asset paths can be overridden via PXpipe_ATLAS_DIR for testing.
 */

import * as fs from 'node:fs';
import * as path from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

function atlasPath(name: 'atlas.json' | 'atlas-gray.json'): string {
  const override = process.env.PXpipe_ATLAS_DIR;
  const dir = override ?? path.resolve(__dirname, '..', '..', 'assets');
  return path.join(dir, name);
}

let _atlasCache: AtlasData | undefined;
let _atlasGrayCache: AtlasData | undefined;

interface AtlasData {
  /* ... определённая в gen-atlas структура ... */
}

export function loadAtlas(): AtlasData {
  if (_atlasCache) return _atlasCache;
  const data = JSON.parse(fs.readFileSync(atlasPath('atlas.json'), 'utf8')) as AtlasData;
  _atlasCache = data;
  return data;
}

export function loadAtlasGray(): AtlasData {
  if (_atlasGrayCache) return _atlasGrayCache;
  const data = JSON.parse(fs.readFileSync(atlasPath('atlas-gray.json'), 'utf8')) as AtlasData;
  _atlasGrayCache = data;
  return data;
}
```

> ⚠️ Загрузка JSON — синхронная; для теста OK.

## Обратная совместимость

### Сломано (для downstream consumers)

- `import { ATLAS } from 'pxpipe-proxy/core/atlas.js'` (если такое использование есть) — `ATLAS` больше не экспортируется; вместо него `loadAtlas()`. Это minor breaking change.

### Обратная совместимость сохранена

- Runtime поведение идентично.
- `npm install pxpipe-proxy` — атласы включены в `files`.

## Особенность Cloudflare Workers

Workers деплои через `wrangler`/`tsc` компилируют `src/` в JS-бандл. JSON-файлы в `assets/` нужно либо:
1. **Копировать в `dist/assets/`** при `tsc` (через `assets` поле в `tsconfig.json` или postbuild step).
2. **Inline в bundle** через `esbuild --loader:.json=file`.
3. **Читать через `import` JSON** (`assert { type: 'json' }`) — bundlers это поддерживают.

Рекомендуется вариант 3:
```ts
import atlasJson from '../../assets/atlas.json' with { type: 'json' };
import atlasGrayJson from '../../assets/atlas-gray.json' with { type: 'json' };
```

> `with { type: 'json' }` — стандартный import attributes (Phase 3). Поддерживается в Node 20+, TS 5.3+, esbuild, Cloudflare Workers. Старый синтаксис `assert { type: 'json' }` deprecate.

### Альтернативный вариант: bundler integration

```json
// tsconfig.json
{
  "compilerOptions": { /* ... */ },
  "include": ["src/**/*", "assets/**/*.json"]
}
```

```ts
// src/core/atlas.ts
import atlasJson from '../../assets/atlas.json';
import atlasGrayJson from '../../assets/atlas-gray.json';

export const ATLAS = atlasJson as AtlasData;
export const ATLAS_GRAY = atlasGrayJson as AtlasData;
```

Это сохраняет **публичный API** — downstream consumers, импортирующие `ATLAS`, продолжают работать. Но это менее эффективно (всегда грузит оба атласа при импорте).

## Открытые вопросы

- **Q1:** Какой подход для Cloudflare Workers — `import` JSON или runtime loader? **Решение:** начать с **runtime loader** (через `fs.readFileSync` через `__dirname`), что требует **отдельной** упаковки атласов в bundle Workers. Это нетривиально. **Возможно, стоит подождать**, пока команда не решит Worker-стратегию.
- **Q2:** Должны ли атласы быть **gzip'нуты** в репо (`.json.gz`)? Git эффективнее хранит. Но распаковка при загрузке добавляет CPU. **Решение:** оставить как JSON (читаемость важнее).
- **Q3:** Можно ли вынести бинарь в git-lfs? Это перекладывает проблему на lfs-инфраструктуру. **Решение:** начать с JSON + gitignore.
